Task 05 — Asynchronous REST API Integration

Consuming public REST endpoints via the Fetch API and async/await, featuring skeleton loading, live query filtering, author sorting, pagination, and modal comment streams.

Section 1

Task Objective & Overview

Official Task Objective: Integrate a public REST API using Fetch API with JSONPlaceholder (https://jsonplaceholder.typicode.com/posts), fetch data, parse JSON, dynamically display posts in cards, add loading animations, handle errors, add search, pagination, and retry functionality.

What this task is about: Web applications rarely store business data statically inside HTML. Instead, they interact with web servers over HTTP protocols by issuing asynchronous network requests to REST endpoints, parsing the returned JSON data, and rendering elements dynamically onto the DOM.

Why this task is important: Asynchronous JavaScript (Promises, async/await, and the fetch() API) is arguably the most critical skill in modern frontend development. Handling network latency, skeleton states, search filtering, and resilient error recovery is essential for any real-world production application.

Section 3

How the Implementation Works

The application lifecycle follows a clean asynchronous flow:

  1. Initialization: When the page loads, fetchPosts() is called. Skeleton placeholder cards are injected immediately into the DOM.
  2. Network Ingestion: await fetch(endpointUrl) transmits an HTTP GET request to JSONPlaceholder.
  3. Status & Parsing: If response.ok is true, the response is parsed via await response.json() into the allPosts array. If not, an error is thrown.
  4. Filtering & Slicing: applyFiltersAndRender() applies active search terms, author constraints, and pagination limits, appending generated card elements to the grid.
  5. Secondary Comments Stream: When a user clicks "View Discussion & Comments", the post modal opens and initiates a secondary asynchronous request to fetch that post's specific comments.
Section 4

Code Walkthrough & Key Snippets

The following snippets from script.js highlight how asynchronous requests, latency tracking, and error handling are implemented.

1. Fetching Data with Async / Await and Latency Measurement:

script.js (Fetch API & Async/Await) JavaScript ES6+ 
async function fetchPosts(endpointUrl = API_ENDPOINT) {
  renderSkeletonLoader();
  const startTime = performance.now();

  try {
    const response = await fetch(endpointUrl);
    const endTime = performance.now();
    statLatency.textContent = `${Math.round(endTime - startTime)} ms`;

    if (!response.ok) {
      throw new Error(`HTTP Error ${response.status}: ${response.statusText}`);
    }

    const data = await response.json();
    allPosts = data;
    applyFiltersAndRender();
  } catch (error) {
    displayErrorNotice(error.message);
  }
}

Clean try/catch flow using standard async/await. Measures performance latency and gracefully captures any network or HTTP exceptions.

2. Secondary Comments Fetching in Modal:

script.js (Nested Resource Fetch) JavaScript ES6+ 
async function openPostModal(post) {
  modalPostTitle.textContent = post.title;
  modalPostBody.textContent = post.body;
  postModal.style.display = 'flex';

  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/posts/${post.id}/comments`);
    const comments = await res.json();
    renderCommentsList(comments);
  } catch (err) {
    commentsContainer.innerHTML = '<p>Failed to load comments.</p>';
  }
}

Demonstrates nested resource fetching where selecting an item triggers an additional API request for relational child data.
