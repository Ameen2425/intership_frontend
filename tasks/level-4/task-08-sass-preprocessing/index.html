Task 08 — CSS Preprocessing with Sass (SCSS)

Architecting design tokens, modular partials, reusable mixin libraries, mathematical functions, and automated build pipelines using Dart Sass.

Section 1

Task Objective & Overview

Official Task Objective: Set up Sass/SCSS, create styles.scss, define reusable variables for colors, typography, spacing, and borders, use nested selectors, mixins, functions or reusable utilities, organize styles using partial files, compile SCSS into CSS, link the generated CSS file to index.html, and include package.json scripts for compiling and watching Sass.

What this task is about: CSS Preprocessors like Sass (Syntactically Awesome Style Sheets) extend vanilla CSS with programming constructs like variables, nested selector hierarchies, parametric mixins, and mathematical functions. Preprocessors organize code across small, modular partial files (e.g. _variables.scss, _mixins.scss) that are automatically compiled into standard, cross-browser CSS before delivery to the browser.

Why this task is important: Maintaining massive monolithic CSS files in large-scale enterprise projects leads to code duplication, naming collisions, and slow development velocity. Sass enforces the DRY (Don't Repeat Yourself) principle, allows centralized design token updates (change a color variable in one place to update hundreds of elements), and is an essential tool in production frontend engineering.

Section 2

Technologies Used & Key Concepts

Dart Sass Engine SCSS Syntax Design Tokens ($variables) Modular Partials (_filename.scss) Modern @use Directive Parametric Mixins (@mixin / @include) Mathematical Functions (@function) BEM & Nested Selectors (&) NPM Build & Watch Scripts
  • Design Tokens (_variables.scss): Centralized variables for colors (navy, cyan, indigo), typography scales, spacing units ($spacing-1 to $spacing-8), and a responsive $breakpoints map.
  • Parametric Mixins & Math Functions (_mixins.scss): @function to-rem($pixel) converting pixels to rems, @mixin glassmorphism(), @mixin respond-to($breakpoint), and @mixin btn-variant().
  • BEM Nested Components (_components.scss): Block-Element-Modifier scoping with the & parent selector to avoid repeating class names.
  • Main Manifest (styles.scss): Imports partials via @use "variables" as *;, sets base resets, and defines layout grids.
  • Automated NPM Pipeline (package.json): Dedicated commands for compilation (npm run build:sass) and live watching (npm run watch:sass).

Section 4

Code Walkthrough & Compilation Comparison

The examples below contrast the author-friendly SCSS source code against the resulting compiled CSS output.

1. Mixins & Functions — SCSS Source vs. Compiled CSS:

_mixins.scss (SCSS Source) SCSS 
@function to-rem($pixel) {
  @return math.div($pixel, 16) * 1rem;
}

@mixin glassmorphism($blur: 14px) {
  background: rgba($color-navy-card, 0.85);
  backdrop-filter: blur($blur);
  border: 1px solid rgba(255, 255, 255, 0.14);
}
css/styles.css (Compiled CSS Output) Compiled CSS 
.feature-panel {
  background: rgba(15, 23, 42, 0.85);
  backdrop-filter: blur(12px);
  border: 1px solid rgba(255, 255, 255, 0.14);
}

The compiler evaluates mathematical functions (like to-rem(32) → 2rem) and expands mixins inline with exact vendor prefixes.

2. BEM Selector Nesting with Parent Selector (&):

_components.scss (SCSS Source) SCSS 
.btn-sass {
  display: inline-flex;
  padding: 0.75rem 1.5rem;

  &--primary {
    background: $color-cyan;
    color: $color-navy-darkest;
  }

  &:hover {
    transform: translateY(-2px);
  }
}
css/styles.css (Compiled CSS Output) Compiled CSS 
.btn-sass { display: inline-flex; padding: 0.75rem 1.5rem; }
.btn-sass--primary { background: #38bdf8; color: #050811; }
.btn-sass:hover { transform: translateY(-2px); }

The parent selector & compiles into flat, high-performance CSS selectors without manual repetition.

Testing Guide & NPM Build Scripts

Expected Output: Clean SCSS compilation into css/styles.css with zero Dart Sass warnings, delivering a dark SaaS design system.

  1. Open Demo in Browser: Open demo.html or view in the embedded window. Verify that all styles, gradients, and layouts display properly.
  2. Verify Compiled CSS Link: Inspect the <head> of demo.html — confirm it links to <link rel="stylesheet" href="css/styles.css">.
  3. Test NPM Build Script: Open a terminal in the root project folder (Cognifyz_Frontend_Internship) and run: 
    npm run build:sass
    Verify that Dart Sass compiles with exit code 0.
  4. Test Live Watch Script: Run npm run watch:sass, modify a token value in _variables.scss (e.g. $color-cyan), and observe instant recompilation within milliseconds.
