Sass Architectural Pillars

Demonstrating how SCSS partials, design tokens, mixins, and BEM nesting combine into maintainable stylesheets.

Design Tokens 🎨

1. Reusable Variables

Centralized brand tokens for colors, spacing, typography, and breakpoints declared in _variables.scss. 

// _variables.scss
$color-navy-dark:  #0a0f1d;
$color-cyan:       #38bdf8;
$color-indigo:     #6366f1;
$spacing-4:        1rem;
$border-radius-lg: 16px;
Mixins & Math ⚙️

2. Parametric Mixins

Reusable mixins for glassmorphism, responsive media queries, and to-rem() math conversion functions. 

// _mixins.scss
@mixin glassmorphism($blur: 14px) {
  background: rgba($color-navy-card, 0.85);
  backdrop-filter: blur($blur);
  border: $border-glass;
}

@function to-rem($pixel) {
  @return math.div($pixel, 16) * 1rem;
}
BEM & Scope 🌳

3. Nested Selectors & '&'

Clean DOM nesting with pseudo-states (&:hover) and BEM element/modifier scoping without repeating class names. 

// _components.scss
.btn-sass {
  display: inline-flex;
  &--primary {
    @include btn-variant($color-cyan, #050811);
  }
  &:hover {
    transform: translateY(-2px);
  }
}
Modularity 📦

4. Partials & @use Directive

Organizing stylesheets into modular files imported via @use to prevent global namespace pollution. 

// styles.scss
@use "variables" as *;
@use "mixins" as *;
@use "components" as *;
Build Workflow package.json scripts

Dart Sass Build & Watch Lifecycle

The development process leverages npm scripts to compile SCSS partials into standard cross-browser CSS in real time:

STEP 01

Authoring SCSS

Developers write structured SCSS in _variables.scss, _mixins.scss, and _components.scss.

STEP 02

NPM Build Command

Run npm run build:sass to invoke Dart Sass and generate expanded CSS with source maps.

STEP 03

Live Watcher

Run npm run watch:sass to automatically recompile when any SCSS partial is modified.

STEP 04

Browser Output

The compiled css/styles.css file is linked directly to HTML with full browser compatibility.
