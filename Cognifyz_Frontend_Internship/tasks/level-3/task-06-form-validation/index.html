Task 06 — Form Styling and Client-Side Validation

Building an accessible candidate application form featuring real-time regex input verification, password entropy strength metering, character counters, and submission modals.

Section 1

Task Objective & Overview

Official Task Objective: Build a registration/contact form with Full Name, Email, Phone Number, Password, Confirm Password, Gender, and Message. Validate required fields, email format, phone numbers, password length, and password matching. Display error messages, success notifications, password toggle, character counter, and clear form functionality.

What this task is about: Web forms collect critical user inputs. Client-side validation inspects and verifies data in the user's browser before allowing submission to a server. This task creates instant, accessible visual feedback that highlights errors as the user types, guides corrective action, and prevents erroneous form submissions.

Why this task is important: Forms represent the primary conversion point of web applications (sign-ups, checkouts, lead forms). Client validation prevents unnecessary network round-trips for invalid payloads, shields backends from garbage submissions, and dramatically improves user experience through clear, contextual feedback.

Section 3

How the Implementation Works

The form leverages event listeners on both input (live typing) and submit:

  1. Input-level Validation: As the user types into any field, dedicated validation functions evaluate the current string against regex rules and length constraints.
  2. Visual State Reflection: The helper function setFieldState() toggles .has-error or .has-success classes on the parent container, sets aria-invalid="true/false", and updates contextual error labels.
  3. Submit Event Interception: The submit event calls e.preventDefault(). If any field fails validation, submission is halted and focus automatically jumps to the first erroneous input.
  4. Submission Confirmation: When all 8 checks succeed, candidate data is compiled into a structured summary and presented inside the success modal.
Section 4

Code Walkthrough & Key Snippets

Below are the key validation patterns from script.js.

1. Regular Expression Validation for Email & Phone:

script.js (Regex Validation Logic) JavaScript ES6+ 
const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/;
const PHONE_REGEX = /^\+?(\d[\d-. ]+)?(\([\d-. ]+\))?[\d-. ]{10,15}$/;

function validateEmail() {
  const val = emailInput.value.trim();
  if (!val) {
    setFieldState('group-email', false, 'Email address is required.');
    return false;
  }
  if (!EMAIL_REGEX.test(val)) {
    setFieldState('group-email', false, 'Please enter a valid email address.');
    return false;
  }
  setFieldState('group-email', true);
  return true;
}

Applies strict email format verification and sets accessible error or success classes on the parent group.

2. Password Entropy Strength Meter:

script.js (Entropy Scoring) JavaScript ES6+ 
function evaluatePasswordStrength(val) {
  let score = 0;
  if (val.length >= 8) score += 1;
  if (/[A-Z]/.test(val)) score += 1;
  if (/[0-9]/.test(val)) score += 1;
  if (/[^A-Za-z0-9]/.test(val)) score += 1;

  /* Updates meter bar width (25%, 50%, 75%, 100%) and color dynamically */
  return score;
}

Evaluates password entropy across character classes and updates the progress bar color from red to green in real time.
